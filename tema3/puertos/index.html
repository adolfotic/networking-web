    Puertos TCP y UDP

    Tema 3. Puertos de red

    1. ¿Por qué necesitamos los puertos?

    En una red, la dirección IP permite identificar una interfaz de red a la que queremos enviar tráfico. Sin embargo, un mismo ordenador puede ejecutar muchos programas que utilizan la red al mismo tiempo.

    Por ejemplo, un servidor puede ofrecer simultáneamente:

    • Una página web mediante HTTP.
    • Una página web segura mediante HTTPS.
    • Acceso remoto mediante SSH.
    • Un servicio de resolución de nombres DNS.

    ¿Cómo sabe el sistema operativo qué programa debe recibir los datos que llegan al ordenador?

    Para distinguir los distintos servicios y aplicaciones se utilizan los puertos de transporte.

    Un puerto es un número que identifica un punto de comunicación asociado a un protocolo de transporte, como TCP o UDP.

    Ejemplo: un servidor web

    Imagina un servidor con la dirección IP 192.168.1.20 que ofrece una web y permite administrar el sistema remotamente.

    Servicio Protocolo Puerto habitual
    Web HTTP TCP 80
    Web HTTPS TCP 443
    Acceso remoto SSH TCP 22
    DNS UDP y TCP, según la operación 53

    La dirección IP identifica el destino en la red IP; el puerto de destino ayuda a identificar el servicio al que se entregarán los datos.

    Los puertos no identifican por sí solos un programa de forma universal: el sistema operativo utiliza el protocolo, la dirección local, el puerto y el estado de la comunicación para gestionar el tráfico.

    2. Dirección IP y puerto

    Una dirección IP y un puerto cumplen funciones diferentes.

    • Dirección IP: identifica una interfaz de red dentro del sistema de direccionamiento IP.
    • Puerto: identifica un punto de comunicación de la capa de transporte.
    • Protocolo de transporte: determina cómo se transportan los datos, por ejemplo, mediante TCP o UDP.

    Podemos representar un destino mediante una dirección IP y un puerto:

    192.168.1.20:80

    En este ejemplo:

    • 192.168.1.20 es la dirección IP.
    • 80 es el puerto de destino.

    Esta notación es habitual para direcciones IPv4. Con IPv6 se utilizan corchetes cuando se añade un puerto, por ejemplo:

    [2001:db8::20]:443

    Ejemplo de acceso a una web

    Si un navegador accede a:

    http://192.168.1.20:80

    está intentando acceder al servidor web de esa dirección IP mediante HTTP, utilizando el puerto TCP 80.

    En una URL HTTP es habitual omitir el puerto 80 porque es el puerto predeterminado del protocolo. De forma equivalente, HTTPS utiliza normalmente el puerto 443.

    Importante: que un servidor utilice el puerto 80 no significa que cualquier aplicación web tenga que utilizarlo. Un servicio web también puede escuchar en puertos como 8080 o 8000.

    3. ¿Qué diferencia hay entre TCP y UDP?

    Los números de puerto se utilizan tanto con TCP como con UDP. Son espacios de puertos independientes: por ejemplo, TCP 53 y UDP 53 no son el mismo punto de comunicación.

    TCP

    TCP es un protocolo de transporte orientado a la conexión.

    Entre sus características principales están:

    • Establece una conexión antes de intercambiar los datos de la aplicación.
    • Proporciona entrega fiable y ordenada de los datos.
    • Detecta pérdidas y retransmite los datos cuando corresponde.
    • Utiliza mecanismos de control del flujo y de congestión.

    Se utiliza habitualmente en aplicaciones como HTTP, HTTPS y SSH.

    UDP

    UDP es un protocolo de transporte sin conexión.

    Sus características principales son:

    • No necesita establecer una conexión TCP antes de enviar datagramas.
    • No garantiza por sí mismo que los datos lleguen.
    • No garantiza por sí mismo el orden de llegada.
    • Tiene una cabecera más sencilla y puede ser adecuado cuando interesa reducir la sobrecarga o gestionar la comunicación desde la propia aplicación.

    Se utiliza, entre otros casos, en consultas DNS, determinadas comunicaciones multimedia y algunos protocolos de tiempo real.

    UDP no es necesariamente más rápido en todas las situaciones, ni TCP es siempre la opción adecuada. La elección depende de los requisitos de la aplicación.

    4. Rangos de puertos

    Los números de puerto van de 0 a 65535, ambos incluidos.

    Se suelen distinguir tres rangos:

    Rango Denominación habitual Uso general
    0–1023 Puertos conocidos o well-known Servicios ampliamente establecidos
    1024–49151 Puertos registrados Aplicaciones y servicios registrados
    49152–65535 Puertos dinámicos o privados Uso dinámico y efímero, entre otros

    Esta clasificación sigue la división habitual de IANA. El uso real depende del sistema operativo, la aplicación y la configuración.

    Puertos de servicio y puertos efímeros

    Cuando un navegador establece una conexión con un servidor web, normalmente intervienen dos puertos:

    • Un puerto de destino del servidor, por ejemplo, TCP 443.
    • Un puerto de origen temporal del cliente, elegido normalmente por el sistema operativo.

    Ejemplo ilustrativo:

    Cliente 192.168.1.35:51824
              |
              | TCP
              v
Servidor 192.168.1.20:443

    En este ejemplo, 51824 es el puerto de origen del cliente y 443 es el puerto de destino del servidor.

    El puerto de origen no tiene por qué pertenecer siempre al rango dinámico: la selección depende del sistema operativo y de la configuración. El ejemplo representa un caso habitual.

    5. Puertos habituales que debemos conocer

    Puerto Transporte habitual Servicio
    20 y 21 TCP FTP: datos en modo activo y control, respectivamente
    22 TCP SSH
    25 TCP SMTP, envío de correo entre servidores
    53 UDP y TCP DNS
    67 y 68 UDP DHCP para servidor y cliente IPv4, respectivamente
    80 TCP HTTP
    110 TCP POP3
    123 UDP NTP, sincronización horaria
    143 TCP IMAP
    443 TCP HTTPS tradicional
    587 TCP Envío de correo mediante SMTP Submission
    993 TCP IMAP sobre TLS
    995 TCP POP3 sobre TLS
    3306 TCP Puerto predeterminado de MySQL
    5432 TCP Puerto predeterminado de PostgreSQL
    8080 Depende del servicio Puerto alternativo frecuente para aplicaciones web

    La tabla muestra usos habituales, no reglas universales. Un administrador puede configurar un servicio para que utilice otro puerto.

    Además, algunos protocolos modernos pueden utilizar otros transportes. Por ejemplo, HTTP/3 utiliza QUIC sobre UDP, habitualmente en el puerto 443.

    6. ¿Qué significa que un puerto esté en escucha?

    Un servidor necesita que una aplicación esté preparada para recibir comunicaciones. En TCP, normalmente se dice que un servicio está en estado de escucha cuando espera nuevas conexiones en una dirección y un puerto determinados.

    Por ejemplo, un servidor web podría escuchar en:

    0.0.0.0:80

    En IPv4, 0.0.0.0 suele indicar que la aplicación acepta conexiones dirigidas a cualquiera de las direcciones IPv4 locales compatibles con esa escucha.

    También podría escuchar en:

    127.0.0.1:8080

    En este caso, la escucha está limitada a la interfaz de bucle local. Normalmente solo podrán acceder a ella aplicaciones del propio equipo mediante esa dirección.

    En IPv6, :: puede representar una escucha en todas las direcciones IPv6 locales, según la configuración del sistema y de la aplicación.

    Puerto en escucha no significa puerto accesible desde Internet

    Para que un cliente remoto pueda acceder a un servicio, deben cumplirse varias condiciones:

    1. La aplicación debe estar ejecutándose y escuchando en la dirección y el puerto adecuados.
    2. La configuración de red debe permitir que el tráfico llegue al equipo.
    3. Los cortafuegos y las políticas de seguridad deben permitir la comunicación.
    4. Si hay un router con NAT, puede ser necesario configurar el encaminamiento o la traducción de puertos.
    5. El servicio debe estar preparado para atender ese tipo de petición.

    Por tanto, ver un puerto en escucha no demuestra que sea accesible desde otro equipo ni desde Internet.

    Del mismo modo, no recibir respuesta de una conexión no demuestra por sí solo que el puerto esté cerrado: pueden existir filtros, problemas de encaminamiento o restricciones intermedias.

    7. Puertos y cortafuegos

    Un cortafuegos aplica reglas para permitir o bloquear tráfico de red.

    Las reglas pueden tener en cuenta, entre otros elementos:

    • La dirección IP de origen.
    • La dirección IP de destino.
    • El protocolo de transporte.
    • El puerto de origen o de destino.
    • El estado de la comunicación.
    • La interfaz de red.

    Por ejemplo, una política podría permitir conexiones TCP entrantes al puerto 443 para ofrecer una web HTTPS y bloquear conexiones entrantes al puerto 22 desde redes no autorizadas.

    Abrir un puerto en el cortafuegos no inicia automáticamente un servicio. Si no hay ninguna aplicación escuchando en el puerto, permitir el tráfico no crea un servidor.

    Tampoco es recomendable abrir todos los puertos. Solo deben exponerse los servicios necesarios, con las medidas de seguridad apropiadas.

    8. Cómo consultar los puertos en Ubuntu

    En los siguientes apartados de este tema utilizaremos herramientas de terminal para observar los servicios y las conexiones.

    Una de las más útiles es:

    ss -lnt

    Las opciones indican:

    • -l: muestra sockets en escucha.
    • -n: muestra direcciones y puertos numéricos, sin resolver nombres.
    • -t: limita la consulta a TCP.

    Para consultar TCP y UDP:

    ss -lntu

    Para mostrar también información de las conexiones TCP y UDP, no solo las que están en escucha:

    ss -tun

    Para ver los procesos asociados cuando se dispone de los permisos necesarios:

    sudo ss -lntup

    No todos los servicios tienen que aparecer en estas consultas. El resultado depende de qué aplicaciones estén ejecutándose, de los protocolos utilizados y de los permisos del usuario.

    9. Ideas fundamentales

    • La dirección IP identifica el destino en la capa IP; el puerto permite distinguir puntos de comunicación de la capa de transporte.
    • TCP y UDP tienen espacios de puertos independientes.
    • El puerto 443 se asocia habitualmente a HTTPS, pero el número de puerto no cifra los datos por sí mismo.
    • Un puerto en escucha indica que existe un punto de comunicación preparado para recibir tráfico; no garantiza accesibilidad remota.
    • Los cortafuegos pueden filtrar las comunicaciones incluso cuando existe un servicio en escucha.
    • Un cliente suele utilizar un puerto de origen temporal para comunicarse con el puerto de destino de un servidor.
