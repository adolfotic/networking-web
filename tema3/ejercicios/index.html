    Ejercicios guiados: puertos de red

    Estos ejercicios permiten practicar la relación entre direcciones IP, puertos, protocolos de transporte y servicios de red.

    Intenta resolver cada ejercicio antes de abrir su solución.

    Ejercicio 1. Identificar IP, puerto y servicio

    Un navegador intenta acceder a la siguiente dirección:

    http://192.168.1.20:8080

    Responde:

    1. ¿Cuál es la dirección IP del servidor?
    2. ¿Cuál es el puerto de destino?
    3. ¿Qué protocolo de aplicación se está utilizando?
    4. ¿Podemos asegurar que el servidor utiliza TCP?
    5. ¿Qué ocurriría si la aplicación web estuviera escuchando en el puerto 80, pero no en el 8080?
    Ver solución 1. La IP del servidor es `192.168.1.20`. 2. El puerto de destino es `8080`. 3. Se está utilizando HTTP, indicado por `http://`. 4. Sí. HTTP tradicional sobre una URL `http://` utiliza TCP. HTTP/3, en cambio, utiliza QUIC sobre UDP y normalmente se identifica mediante una URL `https://`. 5. La conexión al puerto 8080 no llegaría al servicio web del puerto 80. Si no existe un servicio escuchando en el puerto 8080, la conexión podría ser rechazada o no recibir respuesta, según la configuración de red. El puerto forma parte del destino de la comunicación y no se puede sustituir automáticamente por otro puerto.

    Ejercicio 2. Reconocer puertos habituales

    Relaciona cada puerto con su servicio habitual.

    Puerto Servicio
    22 A. HTTPS
    53 B. SSH
    80 C. DNS
    443 D. HTTP
    3306 E. MySQL

    Escribe las correspondencias, por ejemplo: 22-B.

    Ver solución - `22-B`: SSH. - `53-C`: DNS. - `80-D`: HTTP. - `443-A`: HTTPS. - `3306-E`: MySQL. Son puertos predeterminados habituales. Un administrador puede configurar un servicio para que utilice otro puerto.

    Ejercicio 3. TCP y UDP

    Indica si cada afirmación es verdadera o falsa y justifica la respuesta.

    1. TCP y UDP comparten exactamente el mismo espacio de puertos.
    2. TCP proporciona entrega fiable y ordenada de datos.
    3. UDP garantiza que todos los datagramas lleguen a su destino.
    4. DNS puede utilizar tanto UDP como TCP.
    5. Una conexión TCP al puerto 443 garantiza por sí sola que los datos estén cifrados.
    Ver solución 1. **Falsa.** TCP y UDP tienen espacios de puertos independientes. Puede existir TCP 53 y UDP 53. 2. **Verdadera.** TCP ofrece entrega fiable y ordenada a la aplicación, mediante mecanismos como retransmisiones. 3. **Falsa.** UDP no garantiza por sí mismo la entrega ni el orden. 4. **Verdadera.** DNS utiliza habitualmente UDP y también TCP en determinadas operaciones y situaciones. 5. **Falsa.** El puerto 443 se asocia normalmente a HTTPS, pero el cifrado depende del protocolo y de cómo se configure la comunicación, no del número de puerto por sí solo.

    Ejercicio 4. Puerto de origen y puerto de destino

    Un equipo cliente establece una conexión con un servidor web:

    Cliente: 192.168.1.35:51824
Servidor: 192.168.1.20:443
Protocolo: TCP

    Responde:

    1. ¿Cuál es la IP del cliente?
    2. ¿Cuál es el puerto de origen?
    3. ¿Cuál es la IP del servidor?
    4. ¿Cuál es el puerto de destino?
    5. ¿Por qué el cliente no necesita utilizar el puerto 443 como puerto de origen?
    Ver solución 1. `192.168.1.35`. 2. `51824`. 3. `192.168.1.20`. 4. `443`. 5. El cliente normalmente utiliza un puerto de origen temporal elegido por el sistema operativo. El puerto 443 es el puerto de destino habitual del servicio HTTPS. La combinación de protocolo, direcciones IP y puertos permite distinguir las comunicaciones.

    Ejercicio 5. ¿Está el servicio disponible?

    Un administrador ejecuta una consulta de puertos en el servidor y observa:

    LISTEN  0  128  127.0.0.1:8080  0.0.0.0:*

    Responde:

    1. ¿Qué significa LISTEN en este contexto?
    2. ¿En qué puerto escucha la aplicación?
    3. ¿Qué significa que la dirección local sea 127.0.0.1?
    4. ¿Podría acceder normalmente otro equipo de la LAN a través de 192.168.1.20:8080?
    5. ¿Qué tendría que comprobar el administrador si quiere que otros equipos accedan al servicio?
    Ver solución 1. La aplicación tiene un socket TCP preparado para aceptar conexiones. 2. Escucha en el puerto `8080`. 3. `127.0.0.1` es la dirección de bucle local o *loopback*. La escucha está limitada al propio equipo. 4. No, no a través de la dirección LAN si la aplicación solo escucha en `127.0.0.1`. 5. Debe revisar la configuración de escucha de la aplicación, el cortafuegos y la conectividad de red. Si el servicio debe ser accesible desde la LAN, tendrá que escuchar en la dirección adecuada o en todas las interfaces pertinentes, aplicando las restricciones de seguridad necesarias. La salida es ilustrativa; la representación exacta puede variar según la herramienta.

    Ejercicio 6. Un puerto abierto en el cortafuegos

    Un equipo tiene un cortafuegos que permite conexiones entrantes al puerto TCP 8080, pero no hay ninguna aplicación escuchando en ese puerto.

    Responde:

    1. ¿Se ha iniciado un servidor web por permitir el puerto?
    2. ¿Qué diferencia hay entre permitir el tráfico y tener un servicio en escucha?
    3. Si una aplicación comienza a escuchar después, ¿podrá cualquier equipo de Internet acceder a ella automáticamente?
    Ver solución 1. No. La regla del cortafuegos no inicia ninguna aplicación. 2. El cortafuegos decide qué tráfico permite; la aplicación es la que proporciona el servicio y escucha en el puerto. 3. No necesariamente. También influyen las reglas de seguridad, las rutas, el direccionamiento, el NAT del router y las restricciones de la red. Solo se deben exponer los servicios necesarios y con una configuración segura.

    Ejercicio 7. Interpretar una salida de ss

    Un alumno ejecuta:

    ss -lnt

    Y obtiene una salida similar a esta:

    State   Recv-Q Send-Q Local Address:Port  Peer Address:Port
LISTEN  0      128    0.0.0.0:22         0.0.0.0:*
LISTEN  0      128    127.0.0.1:631      0.0.0.0:*
LISTEN  0      511    0.0.0.0:8080       0.0.0.0:*

    Responde:

    1. ¿Qué comando se ha ejecutado y qué muestran sus opciones?
    2. ¿Qué servicio utiliza habitualmente el puerto 22?
    3. ¿Qué diferencia hay entre la escucha en 127.0.0.1:631 y la de 0.0.0.0:8080?
    4. ¿Podemos afirmar que los servicios de los puertos 22 y 8080 son accesibles desde Internet?
    5. ¿Por qué es útil consultar los puertos en escucha?
    Ver solución 1. `ss -lnt`: muestra sockets TCP en escucha, con direcciones y puertos numéricos. 2. SSH, utilizado habitualmente para administración remota. 3. La primera escucha está limitada al bucle local; la segunda se asocia a todas las direcciones IPv4 locales compatibles con esa escucha. 4. No. La salida no informa por sí sola del cortafuegos, NAT, rutas ni accesibilidad desde Internet. 5. Permite identificar servicios que esperan conexiones y detectar exposiciones que deben revisarse.

    Ejercicio 8. Diagnóstico de una aplicación web

    Un alumno instala una aplicación web en un servidor Ubuntu. La aplicación indica que está funcionando y que escucha en el puerto 5000.

    Desde el propio servidor puede abrirla, pero desde otro equipo de la red no.

    Ordena las siguientes comprobaciones según te parezca más razonable y añade alguna más si lo consideras necesario:

    • Comprobar el cortafuegos.
    • Revisar la dirección local en la que escucha la aplicación.
    • Comprobar la IP del servidor.
    • Probar la conexión desde el cliente.
    • Verificar que ambos equipos tienen conectividad de red.
    Ver solución orientativa Un orden razonable sería: 1. Consultar la IP del servidor y verificar que el cliente utiliza la dirección correcta. 2. Revisar con `ss -lnt` en qué dirección y puerto escucha la aplicación. 3. Comprobar que ambos equipos tienen conectividad de red. 4. Revisar las reglas del cortafuegos del servidor y las restricciones intermedias. 5. Probar el acceso desde el cliente con la dirección y el puerto correctos. Si la aplicación escucha únicamente en `127.0.0.1:5000`, otros equipos no podrán acceder a ella mediante la IP LAN. También deben considerarse problemas de encaminamiento, aislamiento de clientes o configuración de la propia aplicación.

    Ejercicio 9. Diseñar una configuración de servicios

    Una pequeña empresa dispone de un servidor Ubuntu con la IP 192.168.10.10. Quiere ofrecer:

    • Una web HTTPS.
    • Administración remota mediante SSH.
    • Una base de datos MySQL a la que solo debe acceder el servidor de aplicaciones de la IP 192.168.10.20.

    Completa la tabla:

    Servicio Puerto habitual Protocolo de transporte ¿Debe permitirse desde cualquier origen?
    HTTPS
    SSH
    MySQL
    Ver solución orientativa | Servicio | Puerto habitual | Transporte | Acceso recomendado | |---|---:|---|---| | HTTPS | 443 | TCP para HTTPS tradicional; HTTP/3 usa QUIC sobre UDP | Permitir desde los clientes previstos | | SSH | 22 | TCP | Restringir a los equipos o redes de administración | | MySQL | 3306 | TCP | Permitir únicamente desde `192.168.10.20`, si esa es la única aplicación autorizada | La política exacta depende de la arquitectura. La base de datos no debería exponerse innecesariamente a toda la red o a Internet.

    Ejercicio 10. Actividad de síntesis

    Un servidor Ubuntu tiene la IP 192.168.1.20/24 y ejecuta una aplicación web en el puerto TCP 8080.

    El administrador observa lo siguiente:

    • Desde el propio servidor puede acceder a http://127.0.0.1:8080.
    • Desde un equipo de la misma LAN no puede acceder a http://192.168.1.20:8080.
    • El servicio aparece en escucha.

    Responde:

    1. ¿Qué significa que funcione el acceso a 127.0.0.1?
    2. ¿Qué información adicional necesitas para determinar la causa del fallo?
    3. ¿Qué comprobarías con ss -lnt?
    4. ¿Qué papel puede desempeñar el cortafuegos?
    5. Explica por qué no basta con saber que el puerto 8080 está en escucha.
    Ver solución orientativa 1. La aplicación responde a través de la interfaz de bucle local. 2. Hay que conocer la dirección de escucha, las reglas del cortafuegos, la conectividad entre equipos y cualquier restricción de red. 3. Si la aplicación escucha en `127.0.0.1:8080` o en `0.0.0.0:8080`, entre otros datos. 4. El cortafuegos podría bloquear conexiones entrantes aunque la aplicación esté preparada para recibirlas. 5. La escucha es solo una condición. La dirección de escucha, la conectividad y las políticas de seguridad también determinan si otro equipo puede acceder.

    Entrega

    Entrega las respuestas a los diez ejercicios. En los ejercicios de diagnóstico, justifica las decisiones en lugar de limitarte a escribir comandos.

    El objetivo no es memorizar números de puerto, sino comprender cómo se relacionan los servicios, las direcciones IP, los protocolos de transporte y las reglas de seguridad.
