    Ejercicios guiados: puertas de enlace y rutas

    1. ¿Necesitamos utilizar la puerta de enlace?

    En los siguientes ejercicios, todos los equipos utilizan IPv4 y las máscaras indicadas. Suponemos que están correctamente configurados, que no existen restricciones de firewall y que las redes tienen conectividad cuando las rutas lo permiten.

    Recuerda:

    • Si el destino pertenece a la misma subred, el equipo intenta comunicarse directamente con él.
    • Si el destino pertenece a otra red, el equipo necesita una ruta adecuada. Habitualmente utilizará la puerta de enlace predeterminada.
    • Tener una puerta de enlace configurada no garantiza que el destino sea alcanzable.

    Ejercicio 1. Comunicación en la misma red

    Un ordenador tiene esta configuración:

    • IP: 192.168.1.10/24
    • Puerta de enlace: 192.168.1.1

    Quiere comunicarse con un servidor cuya dirección es 192.168.1.50.

    Responde:

    1. ¿Pertenecen ambos equipos a la misma subred?
    2. ¿Debe el ordenador enviar el paquete al router para que este lo encamine?
    3. ¿Qué dirección MAC necesitará conocer para enviar una trama Ethernet directamente al servidor?
    Ver solución 1. Sí. Ambos pertenecen a `192.168.1.0/24`. 2. No necesita el router para encaminar el paquete entre redes. Intenta enviar la trama directamente al servidor. 3. Necesita la dirección MAC del servidor. Si no la conoce, puede utilizar ARP para resolverla.

    Ejercicio 2. Comunicación con otra red

    El mismo ordenador 192.168.1.10/24 quiere comunicarse con 192.168.2.50.

    Responde:

    1. ¿Está el destino en la misma subred?
    2. ¿Qué siguiente salto utilizará normalmente?
    3. ¿Qué dirección IP de destino tendrá el paquete enviado?
    Ver solución 1. No. El destino pertenece a `192.168.2.0/24`. 2. Si la ruta predeterminada es `via 192.168.1.1`, utilizará esa puerta de enlace como siguiente salto. 3. La dirección IP de destino del paquete seguirá siendo `192.168.2.50`. La dirección MAC de destino de la trama Ethernet será la de la interfaz del router en la red local.

    2. Comprender el recorrido de un paquete

    Ejercicio 3. Dos redes y un router

    Tenemos esta topología:

    flowchart LR
    subgraph RED1["Red A: 192.168.1.0/24"]
        A["PC A<br/>192.168.1.10"]
    end

    R["Router<br/>192.168.1.1<br/>192.168.2.1"]

    subgraph RED2["Red B: 192.168.2.0/24"]
        B["Servidor B<br/>192.168.2.20"]
    end

    A --- R
    R --- B

    Responde:

    1. ¿Cuántas redes IP aparecen?
    2. ¿Qué direcciones corresponden a las interfaces del router?
    3. ¿Qué puerta de enlace debería utilizar PC A para llegar a la red B, suponiendo que no existe una ruta más específica?
    4. ¿Qué dispositivo encamina el paquete entre las dos redes?
    Ver solución 1. Aparecen dos redes IP. 2. Las interfaces del router utilizan `192.168.1.1` y `192.168.2.1`. 3. PC A utilizará `192.168.1.1` como siguiente salto. 4. El router recibe el paquete y lo reenvía hacia la red B si dispone de una ruta adecuada y el tráfico está permitido.

    3. Interpretar una tabla de rutas

    Ejercicio 4. Leer la salida de Linux

    Un equipo ejecuta ip route y obtiene:

    default via 192.168.1.1 dev enp0s3
192.168.1.0/24 dev enp0s3 proto kernel scope link src 192.168.1.10

    Responde:

    1. ¿Cuál es la puerta de enlace predeterminada?
    2. ¿Qué interfaz se utiliza para llegar a la red local?
    3. ¿Cuál es la dirección IP de origen preferida para la segunda ruta?
    4. ¿Qué ruta se utilizará para un destino de 192.168.1.50?
    5. ¿Qué ruta se utilizará normalmente para un destino de 8.8.8.8, si no existen otras rutas aplicables?
    Ver solución 1. `192.168.1.1`. 2. `enp0s3`. 3. `192.168.1.10`. 4. La ruta conectada `192.168.1.0/24`, porque es una ruta más específica que la ruta predeterminada. 5. La ruta predeterminada, a través de `192.168.1.1`.

    Ejercicio 5. ¿Qué sucede si falta la ruta predeterminada?

    La tabla de rutas de un equipo contiene solamente:

    192.168.1.0/24 dev enp0s3 proto kernel scope link src 192.168.1.10

    Responde:

    1. ¿Puede comunicarse con un equipo de 192.168.1.0/24?
    2. ¿Dispone de una ruta predeterminada en esta tabla?
    3. ¿Podrá llegar necesariamente a 8.8.8.8?
    Ver solución 1. Sí, si el equipo de destino está accesible en la red local. 2. No aparece ninguna ruta predeterminada. 3. No. Con esta tabla no hay una ruta para ese destino. Podría existir otra configuración o una ruta adicional en un sistema real, pero no está representada en el ejemplo.

    4. Elegir la ruta más adecuada

    Ejercicio 6. Ruta específica y ruta predeterminada

    Una tabla de rutas contiene:

    default via 192.168.1.1 dev enp0s3
10.20.0.0/16 via 192.168.1.254 dev enp0s3
192.168.1.0/24 dev enp0s3 proto kernel scope link src 192.168.1.10

    Indica qué ruta se utilizaría para cada destino:

    1. 192.168.1.40
    2. 10.20.30.40
    3. 8.8.8.8
    Ver solución 1. `192.168.1.0/24`, la red directamente conectada. 2. `10.20.0.0/16`, mediante `192.168.1.254`. 3. La ruta predeterminada, mediante `192.168.1.1`. Linux selecciona normalmente la ruta coincidente más específica, es decir, la de prefijo más largo. Si hay varias rutas igualmente específicas, pueden intervenir otros criterios, como la métrica.

    5. Diagnóstico de problemas

    Ejercicio 7. La puerta de enlace no responde

    Un alumno ejecuta:

    ping -c 4 192.168.1.1

    No recibe respuestas.

    ¿Puedes afirmar que el router está apagado? Explica al menos tres posibles causas del resultado.

    Ver solución No. El resultado no demuestra por sí solo que el router esté apagado. Posibles causas: - La dirección de la puerta de enlace es incorrecta. - Existe un problema de conexión física o de configuración de la interfaz. - El router o un firewall bloquea las peticiones ICMP. - El equipo no está correctamente conectado a la red local. - El router está apagado o tiene una avería. Es necesario realizar más comprobaciones antes de determinar la causa.

    Ejercicio 8. Un equipo local responde, pero Internet no funciona

    Un ordenador puede comunicarse con otro equipo de su red local, pero no puede acceder a una dirección IP externa.

    Indica qué comprobarías primero y justifica el orden.

    Ver solución orientativa 1. Ejecutar `ip addr` para comprobar la dirección IP y el prefijo. 2. Ejecutar `ip route` para verificar que existe una ruta adecuada hacia el destino externo. 3. Comprobar la puerta de enlace mediante `ping`, teniendo en cuenta que puede bloquear ICMP. 4. Si la puerta de enlace es accesible, investigar el encaminamiento del router, la conectividad externa y posibles reglas de filtrado. Si se accede a una dirección IP externa pero no a un nombre de dominio, también conviene investigar la resolución DNS. En este ejercicio, el problema descrito no demuestra que DNS sea la causa.

    6. Actividad final

    Diseña una red con estas condiciones:

    • Red A: 192.168.10.0/24.
    • Red B: 192.168.20.0/24.
    • Un router conecta ambas redes.
    • PC A tiene la dirección 192.168.10.10/24.
    • PC B tiene la dirección 192.168.20.20/24.

    Entrega:

    1. Un diagrama de la topología.
    2. Las direcciones IP de las dos interfaces del router.
    3. La puerta de enlace que debe configurar cada PC.
    4. Una explicación del recorrido de un paquete desde PC A hasta PC B.
    5. Dos comandos de Linux que utilizarías para diagnosticar un problema de conectividad.

    Criterios de evaluación

    • Identifica correctamente las dos subredes.
    • Asigna direcciones coherentes a las interfaces del router.
    • Configura la puerta de enlace correcta en cada equipo.
    • Explica el encaminamiento sin confundir direcciones IP y MAC.
    • Propone comandos de diagnóstico adecuados.
