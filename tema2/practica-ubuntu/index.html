    Práctica de Ubuntu: puertas de enlace y rutas

    1. Objetivos

    Al terminar esta práctica, deberás ser capaz de:

    • Consultar la configuración IP de un equipo Ubuntu.
    • Identificar su dirección IP, máscara o prefijo de red.
    • Localizar la puerta de enlace predeterminada.
    • Consultar la tabla de rutas del sistema.
    • Diferenciar una comunicación dentro de la red local de otra que necesita un router.
    • Interpretar el resultado de una consulta de ruta.
    • Realizar un diagnóstico inicial cuando un equipo no tiene conectividad.

    2. Material necesario

    • Un equipo con Ubuntu.
    • Acceso a una terminal.
    • Conexión a una red local, si está disponible.

    Importante: en esta práctica solo consultaremos la configuración. No cambies la dirección IP, las rutas ni la configuración del router.

    3. Consultar la configuración de red

    Abre una terminal y ejecuta:

    ip addr

    Este comando muestra las interfaces de red y sus direcciones.

    Busca la interfaz que estés utilizando. Puede llamarse enp0s3, ens33, eno1, wlp2s0 u otro nombre.

    Anota los datos de tu interfaz:

    Dato Tu resultado
    Nombre de la interfaz
    Dirección IPv4
    Prefijo de red
    Estado de la interfaz

    Por ejemplo, podrías encontrar:

    inet 192.168.1.35/24

    Esto indica que la interfaz tiene la dirección 192.168.1.35 y utiliza un prefijo /24, equivalente a la máscara 255.255.255.0.

    El nombre de la interfaz y la dirección IP de tu equipo pueden ser diferentes.

    Preguntas

    1. ¿Qué dirección IPv4 tiene tu equipo?
    2. ¿Qué significa el número que aparece después de la barra?
    3. ¿Qué máscara de red corresponde a un prefijo /24?
    4. ¿Por qué puede haber varias interfaces de red en un mismo equipo?

    4. Localizar la puerta de enlace

    Ejecuta:

    ip route

    Este comando muestra las rutas que Ubuntu utiliza para decidir por dónde enviar los paquetes IP.

    Un resultado de ejemplo podría ser:

    default via 192.168.1.1 dev enp0s3
192.168.1.0/24 dev enp0s3 proto kernel scope link src 192.168.1.35

    Interpreta cada línea:

    • default: ruta que se utiliza cuando no existe otra ruta más específica aplicable.
    • via 192.168.1.1: dirección IP del siguiente salto, en este caso la puerta de enlace.
    • dev enp0s3: interfaz por la que se envía el tráfico.
    • 192.168.1.0/24: red directamente conectada.
    • src 192.168.1.35: dirección IP de origen que Ubuntu propone utilizar para esa ruta.

    Anota tus resultados:

    Dato Tu resultado
    ¿Aparece una ruta default?
    IP de la puerta de enlace
    Interfaz utilizada para la ruta predeterminada
    Red local que aparece en la tabla

    Preguntas

    1. ¿Qué dirección IP tiene tu puerta de enlace predeterminada?
    2. ¿Por qué suele pertenecer a la misma red local que tu equipo?
    3. ¿Qué diferencia hay entre la dirección IP de tu equipo y la de la puerta de enlace?
    4. ¿Qué podría ocurrir si no existiera una ruta predeterminada y quisieras acceder a una dirección de Internet?

    Si no aparece una ruta default, anótalo. Algunas redes o máquinas virtuales tienen configuraciones especiales; no supongas automáticamente que el equipo está mal configurado.

    5. Comprobar la conectividad con la puerta de enlace

    Si has identificado una puerta de enlace, sustituye 192.168.1.1 por su dirección y ejecuta:

    ping -c 4 192.168.1.1

    La opción -c 4 hace que se envíen cuatro solicitudes y el comando termine.

    Observa el resultado:

    • Si recibes respuestas, existe conectividad IP con la puerta de enlace para estas pruebas.
    • Si no recibes respuestas, no puedes concluir por ese único dato que el router esté apagado. Puede bloquear ICMP, haber un problema de conexión o existir alguna restricción de red.

    Anota:

    • ¿Has recibido respuestas?
    • ¿Qué latencia aproximada muestran?
    • ¿Se ha perdido algún paquete?

    Si estás trabajando en una máquina virtual, ten en cuenta que la topología de red configurada en el hipervisor puede influir en el resultado.

    6. Consultar la ruta hacia un destino local

    Ejecuta:

    ip route get 192.168.1.50

    Este comando consulta qué ruta elegiría Ubuntu para llegar a esa dirección. No envía paquetes al destino.

    En este ejemplo se supone que tu equipo tiene la dirección 192.168.1.35/24 y que no hay rutas especiales que cambien la decisión.

    Interpreta el resultado. Si el destino pertenece a la red local, normalmente Ubuntu indicará la interfaz de salida y no necesitará enviar el paquete a la puerta de enlace.

    Ahora prueba con una dirección de otra red:

    ip route get 8.8.8.8

    Si existe una ruta predeterminada adecuada, el resultado normalmente indicará que el siguiente salto es la puerta de enlace.

    Responde:

    1. ¿Qué interfaz aparece en cada consulta?
    2. ¿Aparece via en ambas consultas o solo en una?
    3. ¿Por qué Ubuntu puede necesitar la puerta de enlace para llegar a 8.8.8.8, pero no para llegar a un equipo de su propia subred?
    4. ¿Qué ocurriría si no existiera una ruta aplicable para uno de los destinos?

    Importante: ip route get consulta la decisión local de encaminamiento. No demuestra que el destino esté encendido ni que sea alcanzable.

    7. Observar una comunicación con otro equipo

    Si tienes otro equipo accesible en la misma red local, consulta su dirección IP y ejecuta:

    ping -c 4 DIRECCION_IP_DEL_OTRO_EQUIPO

    Sustituye DIRECCION_IP_DEL_OTRO_EQUIPO por la dirección real, por ejemplo:

    ping -c 4 192.168.1.50

    Si no dispones de otro equipo, puedes realizar igualmente el apartado anterior con ip route get.

    Contesta:

    1. ¿Responde el otro equipo?
    2. ¿Está en tu misma subred según la IP y el prefijo?
    3. Si no responde, ¿qué otras comprobaciones harías antes de concluir que existe un fallo de red?

    Recuerda que el cortafuegos del destino puede bloquear las solicitudes ping.

    8. Diagnóstico de situaciones

    Lee cada caso e indica qué comprobarías y qué papel desempeña la puerta de enlace.

    Caso A. Funciona la red local, pero no se accede a Internet

    Un equipo puede comunicarse con otros ordenadores de su red, pero no puede acceder a direcciones externas.

    Indica al menos tres posibles comprobaciones. Por ejemplo:

    • Revisar la ruta predeterminada con ip route.
    • Comprobar la conectividad con la puerta de enlace.
    • Comprobar si existe conectividad hacia una dirección externa.
    • Si se alcanza una dirección IP externa, comprobar por separado la resolución DNS.

    No concluyas que el problema es necesariamente la puerta de enlace: también puede haber problemas de encaminamiento más allá del router, filtrado o falta de conectividad externa.

    Caso B. No funciona ni la comunicación local ni la externa

    ¿Qué revisarías primero en ip addr? ¿Qué información adicional consultarías con ip route?

    Caso C. No responde el ping al router

    Enumera al menos tres posibles causas y explica por qué el resultado no demuestra por sí solo que el router esté apagado.

    Caso D. El equipo no tiene ruta predeterminada

    ¿Qué tipo de destinos podría alcanzar todavía? ¿Qué información necesitas para determinar si la configuración es correcta para esa red?

    9. Entrega

    Entrega un documento breve con:

    1. La salida relevante de ip addr y los datos identificados.
    2. La salida de ip route y la identificación de la puerta de enlace.
    3. Los resultados de las dos consultas ip route get.
    4. El resultado de la prueba ping a la puerta de enlace, si dispones de ella.
    5. Las respuestas a las preguntas y los cuatro casos de diagnóstico.
    6. Una conclusión de entre cinco y ocho líneas explicando cómo decide Ubuntu si envía el tráfico directamente a otro equipo o a través de la puerta de enlace.

    Puedes ocultar direcciones públicas o cualquier dato de red que no sea necesario para la evaluación.

    10. Criterios de evaluación

    Criterio Puntuación
    Identifica la IP, el prefijo y la interfaz 2 puntos
    Interpreta la ruta predeterminada y la puerta de enlace 2 puntos
    Compara correctamente las consultas ip route get 2 puntos
    Realiza e interpreta las pruebas de conectividad con prudencia 2 puntos
    Resuelve los casos de diagnóstico y redacta la conclusión 2 puntos
