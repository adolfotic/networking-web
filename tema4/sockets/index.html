    Sockets

    Tema 4. Sockets

    1. ¿Qué es un socket?

    Hasta ahora hemos estudiado las direcciones IP y los puertos. Sabemos que una dirección IP permite identificar un destino en la red y que un puerto permite distinguir distintos puntos de comunicación de una aplicación.

    Un socket es una abstracción del sistema operativo que permite a una aplicación comunicarse mediante una interfaz de programación de red.

    En una comunicación TCP, el socket permite a una aplicación utilizar una conexión de transporte. En UDP, permite enviar y recibir datagramas sin establecer una conexión TCP.

    Para entenderlo de forma intuitiva, podemos distinguir tres conceptos:

    • Dirección IP: identifica una interfaz de red de destino.
    • Puerto: identifica un punto de comunicación de la capa de transporte.
    • Socket: es el mecanismo que utiliza una aplicación para enviar y recibir datos a través de la red.

    La forma exacta de identificar un socket depende del protocolo y del contexto. No todos los sockets representan una conexión TCP establecida.

    2. Relación entre IP, puerto y socket

    Imagina un servidor con la dirección IP 192.168.1.20 que ofrece una web mediante HTTPS.

    El servidor puede tener una aplicación escuchando en el puerto TCP 443:

    Servidor: 192.168.1.20:443

    Un cliente con la dirección IP 192.168.1.35 inicia una conexión desde un puerto de origen temporal, por ejemplo, el 51824:

    Cliente:  192.168.1.35:51824
Servidor: 192.168.1.20:443
Protocolo: TCP

    La comunicación utiliza dos extremos:

    • El extremo local del cliente.
    • El extremo remoto del servidor.

    En TCP, una conexión se identifica por la combinación de los dos extremos y el protocolo de transporte. Habitualmente se habla de una combinación de cinco elementos:

    1. Protocolo.
    2. IP de origen.
    3. Puerto de origen.
    4. IP de destino.
    5. Puerto de destino.

    Esta combinación suele denominarse 5-tupla.

    Diagrama de una comunicación TCP

    flowchart LR
    A["Cliente<br/>192.168.1.35:51824"]
    B["Servidor<br/>192.168.1.20:443"]
    A <-->|"TCP"| B

    El puerto 443 identifica el servicio HTTPS habitual en el servidor, mientras que el puerto 51824 es un ejemplo de puerto de origen del cliente.

    Un servidor puede atender simultáneamente a muchos clientes que se conectan a su mismo puerto de servicio. Las conexiones se distinguen mediante sus extremos y el protocolo.

    3. Socket de escucha y socket de conexión

    Es importante diferenciar un socket que espera conexiones de otro que forma parte de una conexión establecida.

    Socket de escucha

    En un servidor TCP, la aplicación puede abrir un socket y asociarlo a una dirección y un puerto. Después, lo pone en estado de escucha para aceptar nuevas conexiones.

    Ejemplo:

    0.0.0.0:443

    En IPv4, esta dirección suele indicar que el socket escucha en todas las interfaces IPv4 locales compatibles con esa configuración.

    El socket de escucha no representa por sí mismo una conexión con un cliente concreto: está preparado para aceptar conexiones entrantes.

    Socket de conexión establecida

    Cuando un cliente establece una conexión TCP, el sistema operativo mantiene información sobre esa conexión.

    Por ejemplo:

    Cliente: 192.168.1.35:51824
Servidor: 192.168.1.20:443
Estado: ESTABLISHED

    El estado ESTABLISHED indica que la conexión TCP está establecida.

    El servidor puede tener un socket de escucha en el puerto 443 y, al mismo tiempo, varios sockets asociados a conexiones establecidas con clientes diferentes.

    4. ¿Por qué un servidor puede atender a varios clientes?

    Supongamos que tres clientes acceden al mismo servidor web:

    Cliente Puerto de origen Servidor Puerto de destino
    Cliente A 51824 192.168.1.20 443
    Cliente B 51825 192.168.1.20 443
    Cliente C 51826 192.168.1.20 443

    Los tres clientes utilizan el mismo puerto de destino, TCP 443, pero cada conexión tiene un extremo de cliente diferente.

    El sistema operativo mantiene el estado necesario para distinguir las conexiones y entregar los datos a la aplicación correspondiente.

    Los puertos de origen del ejemplo son ilustrativos. El sistema operativo elige los puertos disponibles según sus reglas de asignación.

    Idea clave: un puerto de servidor puede ser compartido por muchas conexiones TCP simultáneas. No es necesario que cada cliente utilice un puerto de servidor diferente.

    5. Sockets TCP y UDP

    Los sockets pueden utilizar distintos protocolos de transporte.

    Sockets TCP

    TCP está orientado a la conexión. Ofrece entrega fiable y ordenada de los datos a la aplicación.

    En un servidor TCP podemos encontrar:

    • Un socket de escucha.
    • Sockets asociados a conexiones establecidas con clientes.

    Por ejemplo, un servidor web HTTPS tradicional puede utilizar TCP 443.

    Sockets UDP

    UDP permite enviar y recibir datagramas sin establecer una conexión TCP.

    Una aplicación puede utilizar un socket UDP asociado a un puerto para recibir datagramas dirigidos a ese punto de comunicación.

    Por ejemplo, DNS utiliza habitualmente UDP 53 y también TCP 53 en determinadas operaciones.

    En UDP no existe el establecimiento de conexión TCP ni el estado ESTABLISHED de TCP. Algunas herramientas pueden mostrar información de sockets UDP de forma distinta a la de los sockets TCP.

    6. Direcciones locales y remotas

    Al consultar sockets, podemos encontrar columnas como estas:

    Local Address:Port
Peer Address:Port

    La dirección local identifica el extremo asociado al socket en el equipo desde el que se realiza la consulta.

    La dirección remota o del extremo opuesto indica el otro extremo cuando existe uno definido para ese socket.

    Ejemplo ilustrativo:

    Local Address:Port       Peer Address:Port
192.168.1.35:51824       192.168.1.20:443

    En este ejemplo:

    • La dirección local es 192.168.1.35.
    • El puerto local es 51824.
    • La dirección remota es 192.168.1.20.
    • El puerto remoto es 443.

    La interpretación de estas columnas depende del estado y del tipo de socket. Un socket de escucha no tiene necesariamente un cliente remoto concreto.

    7. ¿Cómo se consultan los sockets en Ubuntu?

    Ubuntu incluye la herramienta ss, que permite consultar sockets de red.

    Mostrar sockets TCP en escucha

    ss -lnt

    Opciones:

    • -l: sockets en escucha.
    • -n: direcciones y puertos numéricos.
    • -t: sockets TCP.

    Mostrar sockets TCP y UDP

    ss -tun

    Este comando muestra sockets TCP y UDP, con direcciones y puertos numéricos. No se limita a los sockets en escucha.

    Mostrar todas las conexiones TCP

    ss -ant

    Incluye sockets TCP en distintos estados, como escucha, conexiones establecidas y otros estados que existan en el sistema.

    Mostrar procesos asociados

    sudo ss -tunap

    La opción -p solicita información de los procesos asociados a los sockets. Para consultar procesos de otros usuarios pueden ser necesarios permisos elevados.

    La salida depende de los servicios que estén activos y de los permisos disponibles.

    8. ¿Cómo se relaciona un socket con una aplicación?

    Una aplicación utiliza las funciones de red que proporciona el sistema operativo para crear y gestionar sockets.

    En términos generales, un servidor TCP realiza operaciones equivalentes a estas:

    1. Crea un socket.
    2. Lo asocia a una dirección IP y un puerto, cuando corresponde.
    3. Lo pone en escucha.
    4. Acepta conexiones entrantes.
    5. Intercambia datos con los clientes.
    6. Cierra los sockets cuando termina la comunicación.

    Un cliente TCP realiza un proceso distinto:

    1. Crea un socket.
    2. Indica el destino al que quiere conectarse.
    3. Establece la conexión TCP.
    4. Intercambia datos.
    5. Cierra la conexión.

    No es necesario programar estas operaciones para utilizar una aplicación web: el navegador y el sistema operativo se encargan de los detalles.

    Sin embargo, comprender este proceso ayuda a diagnosticar problemas de red y a desarrollar aplicaciones cliente-servidor.

    9. Sockets y servidores web

    Cuando un navegador accede a una aplicación web, intervienen varios elementos:

    1. El navegador determina la dirección del servidor, resolviendo el nombre mediante DNS cuando sea necesario.
    2. El cliente selecciona un puerto de origen disponible.
    3. Se establece la comunicación de transporte adecuada.
    4. La petición llega al servicio web que corresponde.
    5. El servidor procesa la petición y devuelve una respuesta.

    En HTTPS tradicional, HTTP se transmite mediante TLS sobre TCP. HTTP/3 utiliza QUIC sobre UDP.

    Una comunicación web no depende únicamente de que exista un socket. También deben funcionar correctamente el direccionamiento IP, el encaminamiento, el transporte, la aplicación y las medidas de seguridad.

    10. Ideas fundamentales

    • Un socket es una interfaz de comunicación que utiliza una aplicación a través del sistema operativo.
    • IP, puerto y socket son conceptos relacionados, pero no equivalentes.
    • Un socket de escucha TCP espera conexiones; una conexión TCP establecida representa una comunicación concreta.
    • Un servidor puede mantener múltiples conexiones TCP en el mismo puerto de servicio.
    • TCP y UDP utilizan espacios de puertos independientes.
    • La herramienta ss permite observar sockets y sus estados.
    • La existencia de un socket en escucha no garantiza que sea accesible desde otro equipo.
